# HIJACKPOT 플레이테스트·밸런스 점검

기준은 `CLAUDE.md`의 검증과 레퍼런스, 7장 구현 원칙, 8장 MVP 완료 판단 기준이다. 유니티 조작은 `hijackpot-unity-work` 절차를 따른다.

## A. 수치·구조 점검 (코드와 데이터)
1. 룰렛 칸 데이터(`RouletteSegmentData`, 기본 8칸, weight)를 표로 뽑는다: 칸, 타입, 값, weight, 각도(= weight/합 × 360), 확률.
2. 기댓값을 계산한다: SPIN 1회 기대 피해·방어·회복, 적 룰렛 1회 기대 피해. 계산은 스크립트로 해서 검증 가능한 숫자로 제시한다.
3. 시드 재현 확인: 같은 `battleSeed`로 두 번 돌려 같은 결과가 나오는지. 안 되면 원인(`UnityEngine.Random` 직접 호출 등)을 찾는다.
4. 발동 순서가 항상 같은지, 전투 로그로 원인과 순서를 읽을 수 있는지 확인한다. 로그가 부족하면 우선 과제로 표시한다.
5. 위험 신호: 한 칸 확률 과다, 같은 행동이 최선인 턴이 3턴 이상 이어질 구조, 타이밍 실력만으로 빌드가 무의미해지는 구조, 나쁜 운이 즉시 패배로 이어지는 구간.

## B. 플레이테스트 리뷰 (사용자 관찰 기록이 있을 때)
설명 전 행동 위주로 정리한다: 시선, 멈춤, 놓친 UI, 반복 행동, 고민한 선택, 콤보 만족 순간, 패배 원인 이해 여부. 개발 의도보다 실제 행동을 우선한다.

## C. MVP 완료 기준 판정
각 항목을 통과 / 미달 / 측정 불가로 판정하고 근거를 한 줄씩 단다.
- 설명 없이 10초 안에 기본 룰렛 규칙 이해
- 첫 플레이 5분 안에 의미 있는 연쇄 폭발 경험
- 테스터가 빌드 방향과 패배 원인을 설명 가능
- 같은 행동만 하는 턴이 3턴 이상 연속되지 않음
- 패배 후 다른 빌드로 재도전하고 싶은 반응

## 결과물
1. 요약 3줄 (가장 큰 문제, 가장 좋은 점, 다음 할 일)
2. 수치 표와 판정 표
3. 수정 제안: 수치 조정 → 규칙 조정 → 신규 기능 순으로 가벼운 것부터. 신규 기능이 필요하면 `hijackpot-feature-review`로 넘긴다.

결과는 `Docs/playtest/<날짜>-<대상>-<종류>.md`로 저장하고 `Docs/playtest/README.md` 목록에 한 줄 추가한다.
