# Docs — HIJACKPOT 기획·결정 기록

게임을 **왜 이렇게 만들었는지**를 남기는 곳이다. 코드가 "무엇을" 하는지는 코드와 각 폴더 README가, 여기는 "왜"를 맡는다.

| 폴더 | 무엇을 두나 | 언제 쓰나 |
|---|---|---|
| [`adr/`](adr/) | 되돌리기 어려운 설계 결정(ADR) | 나중에 누군가 "왜 이렇게 했지?" 하고 되돌리려 할 만한 결정을 내렸을 때 |
| [`design/`](design/) | 기능 결정 목록, 보류(Later)·미정 항목 | 기능을 Core / Supporting / Polish / Later로 분류하거나 미룰 때 |
| [`playtest/`](playtest/) | 플레이테스트와 밸런스 시뮬레이션 결과 | 테스트·시뮬레이션을 돌렸을 때(날짜별 한 파일) |
| [`pdf/`](pdf/) | 공유용 PDF(1차 MVP 개발·검증 보고서, 전투 단계·순서도)와 원본 HTML | 마일스톤을 정리해 전달할 때 |

## 이 폴더 바로 아래 문서

- [`../CLAUDE.md`](../CLAUDE.md) — 프로젝트 지침 원본(원칙·MVP 범위·작업 규칙)
- [`../CONTEXT.md`](../CONTEXT.md) — 게임 용어집. 코드·UI·문서의 용어는 여기에 맞춘다

## 파일 규칙

- 파일 이름만 봐도 내용이 보이게 쓴다. 날짜가 중요한 기록은 `YYYY-MM-DD-주제.md`.
- 문서 첫 줄 제목과 첫 문단에 "무엇에 관한 문서인지"를 적는다.
- 새 문서를 추가하면 해당 폴더 README의 목록에도 한 줄 추가한다.
